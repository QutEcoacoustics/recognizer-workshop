🗄️ Database Page

This Recognizer Workshop uses "embeddings" to represent audio data in a way that makes it easier to analyze and classify sounds.

Embeddings are numerical representations of audio segments that capture their acoustic features. By converting audio into embeddings, the system can efficiently compare and group similar sounds, making tasks like searching, exploring, and training models more effective.

Specficially this workshop uses Perch embeddings. These are generated by the perch embedding and classification deep neurual network.

Because this Recognizer Workshop is integrated with ecosounds, we can take advantage of the fact that the embeddings are computed by the ecosounds platform.

This step downloads embeddings for your ecosounds project and builds a USEARCH index and sqlite database. This makes is possible to efficiently search and compare embedded audio segments. The database also keeps track of the labelled examples we find which are used to build our recognizer.

You can either

  • Enter a Xeno canto ID (prefixed with "XC")
  • Enter in a url of the reference audio file

Active label: If you are working with multiple labels (i.e. you defined multiple rows in the Target Labels section of the configuration page), you must select which label you are searching for.

🔍 Explore Page

Visualize your audio data in embedding space and discover patterns.

📊 UMAP Visualization

UMAP (Uniform Manifold Approximation and Projection) is a technique that takes the complex, high-dimensional audio embeddings and projects them onto a simple 2D plot that you can visualize. Sounds that are of similar call-type should be close together in the high-dimensional embedding space, but it's hard to draw a plot with 1280 dimensions. Umap figures out how to place each embedding on a 2d space, so that items that are close together in the high dimensional space are also, generally, close together in the 2dimensional projection. This visualization helps you understand the natural groupings and patterns in your data that might not be obvious otherwise.

Creating the UMAP plot involves 3 steps

  1. Learning the function that maps high-dimensional points to the 2D space. This is very time and memory intensive, so we do this with a random subset of your database just once.
  2. Running all the data through that function, giving each and every audio clip a 2D position
  3. Rendering the positive and negative items for the labelled data
If new labels are added you only need to redo step 3.

The "generate UMAP model and cache" button performs steps 1 and 2 and 3

🎓 Train Page

Train machine learning models using your labeled examples. The training process uses several key parameters to control how the model learns from your data.

⚙️ Algorithm Training Parameters

These three parameters control how the training algorithm learns:

  • Learning Rate: How much to update the model weights at each step. Higher values learn faster but may be unstable.
  • Number of Steps: How many times to look at all the labeled examples when training. More steps can improve performance but take longer.
  • Batch Size: How many labeled examples to look at at once. Larger batches can be more stable but require more memory.

📊 Labeled Data Parameters

These parameters control how your labeled data is used during training:

  • Train Ratio: A random subset of your labeled audio is not used to train the model, but instead is used to test it. This helps you know roughly how well the model does on classifying examples that it has never seen before.
  • Weak Negative Weight: Your database contains a lot of audio, most of which is probably not your target species. By taking some random clips from your unlabeled audio and treating them as negative examples, we can train on a wider variety of negative examples than what has been explicitly labeled as negative. However, because we don't know for sure that this process didn't choose a positive example by chance, we give each one less importance in the training.
  • Weak Negatives Batch Size: How many of these randomly chosen examples to include for each batch (on top of the number in the strongly labeled batch).

Training Metrics

Metrics measuring performance on the testing split. Here is what each value means:

Aggregate metrics:

Threshold-independent metrics, measuring whether positive examples tend to have higher scores than negative examples:

  • Top-1 Accuracy (top1_acc): For each evaluation clip, checks whether the model's highest-scoring label is correct. A value of 0.80 means the top guess was correct for about 80% of evaluation clips.
  • ROC AUC (roc_auc): Measures how well the model ranks true examples above false examples across all score thresholds. 0.5 is roughly random ranking, and 1.0 is perfect ranking.
  • CMAP (cmap): Class mean average precision. Summarizes how well true positives are ranked near the top for each class, then averages across classes. Higher is better, especially when positives are rare.

Threshold-dependent metrics, measuring whether positives tend to have positive scores and negatives tend to have negative scores:

  • Micro Precision: Precision computed by pooling all class decisions together: $TP / (TP + FP)$.
  • Macro Precision: Precision computed per class and then averaged equally across classes.
  • Micro Recall: Recall computed by pooling all class decisions together: $TP / (TP + FN)$.
  • Macro Recall: Recall computed per class and then averaged equally across classes.
  • Micro F1: F1 score from pooled counts across classes: $2TP / (2TP + FP + FN)$.
  • Macro F1: F1 score computed per class and then averaged equally across classes.
Per class metrics:
  • ROC AUC (Per Class) (roc_auc_individual): A separate ROC AUC value for each target class.
  • CMAP (Per Class) (cmap_individual): A separate average precision value for each target class.
  • TP (True Positives): Items where the class is present and the model predicted present.
  • FP (False Positives): Items where the class is absent but the model predicted present
  • FN (False Negatives): Items where the class is present but the model predicted absent (includes *'implied negatives').
  • TN (True Negatives): Items where the class is absent and the model predicted absent (includes *'implied negatives').
  • Support: Number of true positive examples for that class in the evaluation set.
  • Precision: For that class only, $TP / (TP + FP)$.
  • Recall: For that class only, $TP / (TP + FN)$.
  • F1: For that class only, harmonic mean of precision and recall: $2TP / (2TP + FP + FN)$.
  • * Implied negatives: for multiclass recognizers, items labelled as positive for class A but not labelled at all for class B are assumed to be negative for class B for the purpose of these metrics

✨ Refine Page

Improve your models through iterative refinement. This is also known as "Agile Modeling" or "active learning".

  1. Search the database using your trained model
    • Active LabelThe label to search for
    • Num resultsReturns this many results that most closely match the target score
    • Target scoreThe score to match when searching for results
  2. Review the results and assign positive or negative labels.
    • Tap once for green (positive)
    • Tap twice for red (negative)
    • Tap three times to return to no label (unsure)
